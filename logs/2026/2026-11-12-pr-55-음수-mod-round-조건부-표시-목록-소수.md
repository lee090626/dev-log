### 1. 이번 변경에서 해결한 것

**문제**
추가된 문법 - **음수**: 이름 줄에 `can be negative` → i32 규칙. 페이지 값도 `save diff = 0 can be negative`. 범위 검사를 i64 구간으로 바꿔 i32 범위까지 증명. `/`·`mod`·`round`는 음수 규칙에서 거부. - **mod / round**: `a mod b`는 새 연산 `Rem`(파서→AMI→Z3 bvurem→WASM i32.rem_u→JS)로 구현, 0 나눗셈은 증명으로 막음. `round(a / b)`는 `(a + b/2) / b`로 번역. - **조건부 표시**: `show "text" if cond` → 기존 `when cond show`. - **목록**: `prices[3]`은 `prices_1..3` 입력으로 펼침. `sum/min/max/count(prices)`, `prices[1]`, 목록에 대한 `need`는 항목마다 적용. 페이지 `save prices[3] = 0`, `ask prices "Price"`(칸 3개), 호출 시 `cart(prices)`. - **소수**: `with 2 decimals` → 값×10^N 정수로 저장, `*`·`/`는 AST에서 자릿수 보

**diff에서 자동으로 판별하지 못했습니다.** (LLM 키가 없어 자동 요약으로 기록됨 — 직접 보완)
